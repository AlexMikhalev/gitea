# carries it. Reserving the files additionally makes the edit *visible*:
# without these entries, a PR that deletes three lines from this file reports
# "PASSED - no reserved paths touched" and the next PR silently inherits the
# weakened list. With them, narrowing the guard costs a `sync-owner` label,
# which is the review checkpoint.

# is a database object, not a repository artefact, so it has to be provisioned
# once by hand: the terraphim/gitea maintainer driving the #43-#51 sync owns
# creating it and applying it, and the exact step is recorded in
# docs/plans/design-blast-radius-guard-2026-08-01.md ("Setup - the `sync-owner`
# label"). Creating and applying it both need repository write access, so an
# outside contributor cannot self-exempt.

# --- the workflow directory that would shadow the guard ---------------------
# modules/actions/workflows.go ListWorkflows() (see the loop over
# setting.Actions.WorkflowDirs, default [".gitea/workflows", ".github/workflows"])
# breaks on the FIRST directory that resolves - it does not union them. This
# fork ships its CI in .github/workflows/, so a PR that adds any file under
# .gitea/workflows/ hides every .github/workflows/* workflow, this guard
# included, from the moment it merges.
# Scope: `.gitea/workflows/*`, not `.gitea/*`. The shadowing is a property of
# the `.gitea/workflows` directory resolving, not of `.gitea` existing -
# ListWorkflows stats each WorkflowDirs entry, and `.gitea` alone is not one of
# them. `.gitea/issue_template.md` is already tracked and is unrelated to
# workflow discovery, so reserving the whole subtree taxed legitimate .gitea/
# work for nothing. `*` spans `/`, so this entry still covers any depth
# underneath .gitea/workflows/.
